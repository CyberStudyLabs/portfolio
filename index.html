Fleet Board & HOS Board

Internal tool · in daily use

A zero-install fleet maintenance dashboard that replaces the manual process of exporting CSVs from inspection platforms like Whip Around and merging them by hand. A single HTML file — no server, no install, no data leaving the machine — that ingests raw platform exports and renders a live operations board.

My role: product design, domain modeling, specification, and daily iteration against real data.

  • Custom CSV parser that flattens a stacked multi-header export format covering 78 different form schemas in a single file
  • Work-order pipeline with automatic aging alerts, plus a cross-referenced repair tracker that matches failed inspections to work orders and flags the ones that never got one
  • Status-agnostic pipeline cards that adapt to any company's custom workflow names; day-over-day trend deltas via snapshot persistence
  • The no-dependency, no-backend constraint was the design requirement — built for locked-down workplace machines
  • Companion tool, HOS Board, merges driver hours-of-service reports from two separate systems (Samsara and Alijex) for morning distribution — cut a 20–30 minute daily task to 5 minutes
  • Next step in development: direct Whip Around API integration (access granted) to replace the CSV export step entirely

JavaScript · HTML/CSS · localStorage

Dispatch Operations Platform

In development · in review with leadership

A centralized dispatch and compliance system designed to replace a seven-tab Excel workbook used by a trucking dispatch department. The spreadsheet worked, but any user could edit any field, no changes were logged, and information didn't cross departments — driver availability entered by dispatchers never reached compliance, which is how I found the problem in my own reporting.

My role: product design, domain modeling, specification, and iteration.

  • Role-based permissions across admin, manager, and dispatcher views — dispatchers see availability status only, compliance records stay restricted
  • Audit trail writing an entry per save, replacing a workbook with no change history
  • Driver roster with carrier assignment, HOS clocks, seven-day violation tracking from Samsara, and conflict detection; load reports imported from Aljex
  • Onboarding and recruiting pipeline — new-driver review queue, paperwork tracking, and the follow-up items that outlast onboarding
  • Delivery exception tracking plus reporting filterable by date range and carrier
  • Account and access management covering non-driver staff alongside the driver roster
  • Consolidates dispatch, HOS, onboarding, and compliance into one board so every department works from the same information
  • Next step in development: Samsara API integration for live HOS data, replacing the current manual morning export

CodeWorld

Prototype · in development

A gamified coding platform for ages 10–14 that teaches real code — Python, then HTML/CSS, then JavaScript — not drag-and-drop puzzle pieces. Students finish by building a four-page interactive web app of their own.

  • 14-chapter curriculum with three "Mini Boss" checkpoint challenges; every chapter project feeds into the final capstone, so nothing kids build is throwaway
  • Deliberate scaffolding progression: drag-and-drop pieces through guided typing to fully independent coding, with kid-friendly error names mapped to real Python errors
  • Themed "Worlds" (animal sanctuary, superhero HQ, and more) and a guide character, Vari, who evolves alongside the student
  • Built an SVG character rig with pose and expression controls for producing Vari's art — playtesting turned it into an in-game toy where kids pose Vari and export PNGs into their own projects, giving them free characters and the game organic brand reach
  • Chapters 1–5 and the first Mini Boss are prototyped and playtested with kids

About

I started building software to solve problems in front of me: training materials I wished existed, and reporting work in fleet operations that consumed hours of my day. Those projects grew into NovaCore Technologies, the company through which I develop and operate my products.

A consistent theme across my work is education — training SOC analysts, teaching kids to program, helping new CDL drivers with compliance. I'm currently designing a caregiver-support platform for families managing dementia.

How I work: my strength is architecture and domain knowledge — modeling how a system should behave, writing the specifications, designing the data relationships and integrations, and reviewing implementations against them. I write and maintain the code as well, working in standard code editors along with AI development tools. The domain knowledge behind these products — DOT compliance, security operations, instructional design — comes from my own work experience in those fields.
